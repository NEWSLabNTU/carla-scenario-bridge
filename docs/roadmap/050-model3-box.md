# Phase 050: The Model 3's Box in Every Scenario

Every scenario that names CARLA's `vehicle.tesla.model3` must declare the car's measured
box and axles, for the ego and for NPCs alike, and a lint must keep it that way. Today 128
of 132 such definitions declare a box 29 cm short, 31 cm too tall and centred 3.2 cm off the
rear axle. So SSv2 measures distances, time to collision and contacts on a car that is not
the one Autoware drives or the one CARLA simulates. This phase runs before
[049](049-vehicle-spec.md), whose catalog then starts from correct numbers. Design:
[design/vehicle-side.md](../design/vehicle-side.md), "What exists" and "SSv2 uses the same
car".

**Status**: draft, 2026-10-23.

ego and NPCs".

## Where it starts (2026-10-23)

Counted over every `.xosc` in `src/swb_examples/` and `scenarios/`:

| | definitions | wrong | right |
|---|---|---|---|
| ego (`vehicle.tesla.model3`) | 27 | 25 | 2 |
| NPCs and background AV (`vehicle.tesla.model3`) | 105 | 103 | 2 |
| any other vehicle named by a CARLA blueprint | 0 | | |
| the AWF YAML scenarios (`awf/*.yaml`, the ego placeholders) | 2 | 0 | 2 |

The wrong ones declare `Center (1.5, 0, 0.9)`, `Dimensions 4.5 x 2.1 x 1.8`, and axles
3.1 m apart, track 1.8 m, wheel diameter 0.6 m. The car is:

- 4.792 x 2.163 x 1.488 m (`carla_world/config/blueprint_boxes_0.9.16.yaml`);
- 3.005 m wheel base, 1.667 m track, 0.74 m wheel diameter (acb's `vehicle_info`, measured
  by `extract_vehicle_params.py`);
- so the box centre sits 1.532 m ahead of the rear axle and 0.744 m up.

By file: bench 80 (generated by `gen_npc_benchmark.py`), gap 23, basic 11, demo incidents 6
(`gen_demo_incidents.py`), demo tour 1 (`gen_demo_tour.py`), surfaces 3, multi_av 2,
isaac 2, tutorial 1, and `scenarios/demo/town01_i6_cyclist_inside.xosc` 1.

Why it matters beyond the numbers:

- The bridge shifts every pose by the declared centre (`OriginOffset`). SSv2's ego origin is
  3.2 cm off Autoware's `base_link`.
- The box front is 3.75 m ahead of the rear axle in SSv2 and 3.93 m on the car, so every
  freespace distance to something ahead is 18 cm long.
- The gap oracle compares SSv2's declared box with CARLA's body, so it has been measuring
  this error as part of every gap.

## Design (as proposed)

- **The measured table grows the axles.** `scripts/measure_blueprint_boxes.py` also
  records, from each vehicle's `physics_control`, the rear axle's x from the actor origin,
  the wheel base, the track and the wheel radius. `blueprint_boxes_0.9.16.yaml` is
  regenerated, and `blueprint_boxes.rs` reads and ignores the new keys.
- **One function writes the box.** A small Python module, `scripts/scenario_vehicle.py`,
  returns the OpenSCENARIO `BoundingBox` and `Axles` for a blueprint from the table:
  - centre x = the box centre's x minus the rear axle's x;
  - centre z = height / 2, since SSv2's entity origin is on the ground;
  - axles from the wheel geometry, rear axle at x 0.

  The three generators use it. `Performance` stays per scenario (049).
- **The lint** (`scripts/check_scenario_vehicles.py`, run by `just test`): every `<Vehicle>`
  whose `name` is a blueprint in the table must declare that box and those axles within
  2 cm. Failures name the file, entity, field, declared and measured values.
  - An entity may opt out only with an OpenSCENARIO `<Property name="swb.box_exempt"
    value="<reason>"/>`. The lint lists every exemption it allows.
  - None is expected: the gap scenarios' deliberate mismatches (`town01_truck_pass`'s 12 m
    truck) are declared under other names with `model3d`, not named
    `vehicle.tesla.model3`.

## Steps

- [ ] **S1. Baseline**, on the current boxes, CARLA, on this checkout's CARLA (port 2010):
  - `town01_ego_drive`, `town01_pedestrian`, `town01_traffic_light`, the six incidents and
    the tour: pass or fail, the minimum freespace distances SSv2 logs, time to collision,
    and the stop distance to the pedestrian (incident 2);
  - the gap set (`entity_bodies`, `motorbike_body`, `npc_shoulder`, `truck_pass`): the gap
    oracle's report;
  - `town01_two_av` and `town01_simulator_autopilot`;
  - the 20-NPC bench, once (the frame budget should not move).
- [ ] **S2. Axles in the table**: extend the measure script, regenerate the table, update
  `blueprint_boxes.rs`'s tests.
- [ ] **S3. `scenario_vehicle.py` and the generators**: switch the three generators to it
  and regenerate. The diff must touch only the Model 3's `BoundingBox` and `Axles`.
- [ ] **S4. Hand-written scenarios**: rewrite the rest with the same module (a one-off
  rewrite script, kept in `scripts/`), and check the diff the same way.
- [ ] **S5. The lint** in `just test`. Then edit one box back to 4.5 m and check that it
  fails, naming the file and entity.
- [ ] **S6. Fixtures and docs**: the Rust and Python tests that build a Model 3 from the old
  numbers (`coordinator.rs`, `gap_trace.rs`, `contact_report.rs`, the carla_world tests)
  move to the table's values where they model the car, and stay where they test arithmetic
  only. Also the starter-scenario docs and the comments in the scenarios that quote 1.5 m
  or 4.5 m.
- [ ] **S7. After**: S1's runs again, and a before and after table in this doc's results.
  Every change must be explained by the box, or found and fixed.

## Acceptance

- [ ] The lint passes over every `.xosc`, and fails on a planted wrong box.
- [ ] Regenerating with the three generators reproduces the committed files byte for byte.
- [ ] S1's scenarios pass or fail as before. Each moved number (freespace distances, time
  to collision, contact times, gap reports, `town01_truck_pass`'s overlap depth) is
  explained by the box in the results table. Expect, for example, distances to things ahead
  about 18 cm shorter.
- [ ] `town01_truck_pass` still reports G1 on the ego-truck pair and no CARLA contact.
- [ ] The 20-NPC bench's frame budget is unchanged within its run-to-run spread.
- [ ] `just test`, `just check` pass.

Not in this phase: `Performance` (four sets today; 049 derives it from the spec); boxes of
NPCs declared by size rather than blueprint name (their bodies are picked to fit them,
022); the catalog (049); Isaac runs. Isaac reads the same scenarios, so the change carries
over, and the next Isaac run on server139 checks it.
